# OpenCTF backend

## Requirements

- Go 1.27+
- PostgreSQL
- Docker (only needed to spawn challenge instances with `INSTANCE_PROVIDER=docker`)
- [sqlc](https://docs.sqlc.dev/en/latest/overview/install.html) (only needed when changing SQL)

## Configuration

| Variable            | Default        | Notes                               |
| ------------------- | -------------- | ----------------------------------- |
| `DATABASE_URL`      | _(required)_   | `postgres://user:pass@host:5432/db` |
| `SECRET_KEY`        | _(required)_   | Used to sign auth tokens            |
| `INSTANCE_PROVIDER` | `docker`       | `docker` or `kubernetes`            |
| `HOST_DOMAIN`       | `localhost`    |                                     |
| `UPLOAD_DIR`        | `/app/uploads` |                                     |
| `ADDR`              | `:8000`        | Listen address                      |

## Running

```sh
go run ./cmd/server
```

Migrations in `internal/database/migrations` are embedded in the binary and applied on startup. This means you won't need to run `goose` manually, but you can still use it if you want to inspect the database. This also means that the database must be reachable when starting the server, otherwise it will fail to start.

## Layout

```
cmd/server/            entrypoint: config, database, server lifecycle
internal/config/       environment configuration
internal/database/     pool, migrations, Store (transactions) and error helpers
  migrations/          goose migrations, embedded in the binary
  queries/             sqlc query files
  dbgen/               sqlc-generated code
internal/httpserver/   route wiring, http.Server, request logging middleware
internal/httpx/        JSON request/response helpers
internal/auth/         /api/auth handlers and auth middleware
  passwords/           password hashing
  sessions/            signed session tokens
internal/challenges/   /api/challenges handlers and flag checking
internal/users/        /api/users handlers (public profiles)
internal/teams/        /api/teams handlers and the team ranking
internal/scoreboard/   /api/scoreboard live websocket
internal/instances/    challenge instance and /api/admin/instances handlers, Docker/Kubernetes providers
```

## Tests

```sh
go test ./...
```

Tests that need a database are skipped unless `TEST_DATABASE_URL` points at a Postgres instance.

## Changing SQL

Queries live in `internal/database/queries` and the schema is defined by the goose migrations in `internal/database/migrations`.
The Go code in `internal/database/dbgen` is generated by sqlc. Don't edit it by hand.

1. Install sqlc:

   ```sh
   go install github.com/sqlc-dev/sqlc/cmd/sqlc@latest
   ```

2. (only when required) Add a new migration (`internal/database/migrations/0000N_description.sql`).
3. Edit the SQL queries in `internal/database/queries/*.sql`.
4. Regenerate:

   ```sh
   sqlc generate
   ```

5. Commit the generated files together with the SQL change.
